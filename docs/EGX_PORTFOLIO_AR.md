# مستشار المحفظة المصرية

هذه الطبقة تحول المشروع إلى مستشار محفظة للبورصة المصرية فقط. لا تحتوي على
تكامل مع وسيط، ولا تُنشئ أوامر تنفيذ، وكل مخرجاتها بحثية قابلة للمراجعة.

## السياسة الافتراضية

- رأس المال الابتدائي: 10,000 جنيه
- المساهمة الشهرية: 1,000 جنيه
- الأفق: من 3 إلى 12 شهرًا
- الحد الأقصى المقبول للتراجع: 20%
- 4 إلى 5 أسهم
- سيولة مستهدفة من 10% إلى 20%
- حد أقصى 25% للسهم و40% للقطاع
- الأولوية لعضوية مؤشر EGX الشرعي الموثقة رسميًا، ثم المراجعة المستقلة
  الموثقة محليًا ببصمة رقمية
- لا شراء عند نقص الأدلة؛ ولا بيع لمركز قائم اعتمادًا على بيانات قديمة

هذه حدود للمخاطر وليست ضمانًا لعدم تجاوز التراجع في السوق الفعلي.

## المصادر المقبولة

| المفتاح | الجهة | أقصى عمر |
|---|---|---:|
| `egx_prices` | البورصة المصرية | 7 أيام |
| `egx_disclosures` | البورصة المصرية | 30 يومًا |
| `egx_financial_statements` | البورصة المصرية | 220 يومًا |
| `egx_sharia_constituents` | البورصة المصرية أو الرقابة المالية | 220 يومًا |
| `cbe_macro` | البنك المركزي المصري | 90 يومًا |
| `capmas_inflation` | الجهاز المركزي للتعبئة العامة والإحصاء | 90 يومًا |
| `fra_rules` | الهيئة العامة للرقابة المالية | 365 يومًا |

يُتحقق من اسم النطاق كاملًا قبل الاتصال. لا يُقبل مثلًا
`egx.com.eg.attacker.example`. التحويلات الشبكية التلقائية معطلة، والاستجابة
محدودة الحجم ويجب أن تكون JSON. عند تعذر الموقع يمكن استيراد نسخة موثقة،
ويحفظ النظام SHA-256 ومتى نُشرت ومتى أصبحت معروفة له.

## التشغيل

بعد تثبيت المشروع:

```bash
pip install -e .
egx-portfolio --help
```

اطبع مخطط JSON الكامل لملف المحفظة:

```bash
egx-portfolio snapshot-schema > portfolio-snapshot.schema.json
```

استورد حزمة دليل محفوظة:

```bash
egx-portfolio import-evidence evidence-bundle.json \
  --database egx-evidence.sqlite3 \
  --expected-source egx_sharia_constituents
```

أنشئ الخطة:

```bash
egx-portfolio plan portfolio-snapshot.json \\
  --database egx-evidence.sqlite3 \\
  --output egx-output
```

قبل بناء الخطة يطابق الأمر كل مرجع في ملف المحفظة بسجل موجود داخل قاعدة
الأدلة ويعيد فحص بصمة محتواه؛ المرجع المصطنع أو غير المخزن يوقف التشغيل.

يخرج الأمر ملفين:

- `portfolio_plan.json`: نتيجة منظمة قابلة للاختبار والمعالجة
- `portfolio_plan.md`: تقرير عربي للمراجعة البشرية

لا يستبدل الأمر تقريرًا موجودًا إلا مع `--force`.

## رموز الخروج

| الرمز | المعنى |
|---:|---|
| 0 | أُنشئت خطة مستوفية للحواجز |
| 1 | خطأ في الإدخال أو الحفظ |
| 2 | حُفظ تقرير، لكن التوصية محجوبة بسبب نقص أو عدم صلاحية الأدلة |

## صيغة حزمة الدليل

```json
{
  "schema_version": 1,
  "source_key": "egx_sharia_constituents",
  "source_url": "https://beta.egx.com.eg/ar",
  "published_on": "2026-09-01",
  "observed_at": "2026-09-02T09:00:00+00:00",
  "authority": "official",
  "subjects": ["EFID.CA", "SWDY.CA"],
  "payload": {
    "tickers": ["EFID.CA", "SWDY.CA"]
  }
}
```

الوقت `observed_at` يجب أن يحتوي على منطقة زمنية ويُحوّل إلى UTC. الحقول
الإضافية غير المعروفة مرفوضة في حزمة الدليل.

## بوابة الجاهزية

طبقة الجلب العامة ومسار الاستيراد موجودان، لكن
`egypt_data_adapters_ready` يظل `false` عمدًا إلى أن تُحدد وتُختبر نقاط
النهاية الرسمية الفعلية لكل مصدر وتُراجع شروط استخدامها. لذلك لا ينبغي وصف
النسخة الحالية بأنها خدمة إنتاجية ذات تغذية حية، حتى لو كان محرك القرار
وحواجزه قابلين للاستخدام مع ملفات بيانات موثقة.

## محرك الفرص المتقدم

أضيفت طبقة منفصلة لاكتشاف الفرص ومراجعة المراكز القائمة. لا تعتمد هذه الطبقة
على درجة واحدة فقط، بل تفصل بين جودة النشاط، التقييم، التوقيت، المحفزات،
السيولة والمخاطر. تغير حالة السوق الأوزان بدرجة محدودة فقط حتى لا يتحول
النظام إلى مطاردة قصيرة الأجل لعامل واحد.

كل فرصة جديدة تمر على البوابات التالية:

1. دليل محفوظ ومؤرخ وصالح وقت القرار.
2. تصنيف شرعي مسموح وفق سياسة المحفظة.
3. درجة مركبة وثقة كافيتان.
4. نطاق قيمة عادل يضم حالة ضعيفة وأساسية وقوية.
5. عائد أساسي متوقع يتجاوز الحد الأدنى.
6. خسارة الحالة الضعيفة لا تتجاوز حد المخاطر.
7. مقارنة تكلفة الاستبدال وهامش أمان قبل تدوير مركز قائم.

غياب نطاق تقييم صالح لا ينتج أمر شراء جديد مهما كانت الشركة قوية. كما أن
التقييم القديم لا يستطيع إجبار النظام على بيع مركز قائم؛ يتحول القرار إلى
الانتظار حتى وصول دليل صالح.

### حالات الفرصة

- `high_conviction_buy`: جميع بوابات الدرجة والثقة والعائد والجانب الهابط مستوفاة.
- `buy`: بوابات الشراء الأساسية مستوفاة.
- `add`: مركز قائم ما زال يستحق الزيادة وفق الأدلة الحالية.
- `hold`: الاحتفاظ دون زيادة.
- `watch`: مرشح بحث واعد لم يستوف كل بوابات الشراء.
- `trim`: تقليل مقترح بسبب انكماش العائد المتوقع أو ضعف الجودة.
- `exit`: مراجعة خروج مبنية على أدلة حديثة.
- `blocked`: البيانات أو السياسة تمنع اتخاذ قرار.

هذه مسميات بحثية استشارية ولا تنشئ أوامر لدى أي وسيط.

### تشغيل لوحة الفرص

اطبع مخطط الإدخال:

```bash
egx-portfolio opportunity-schema > opportunity-request.schema.json
```

أنشئ لوحة الفرص:

```bash
egx-portfolio opportunities opportunity-request.json \\
  --database egx-evidence.sqlite3 \\
  --output egx-output/opportunity_board.json
```

للبحث عن أسهم جديدة بالفعل، يجب أن يحتوي `snapshot.candidates` على الكون
الاستثماري المراد مسحه، لا على الأسهم التي اختارها المستخدم مسبقًا فقط.
عند تغذية كامل الأسهم المؤهلة في البورصة، تقوم اللوحة بفصل المرشحين الجدد عن
المراكز الحالية وترتيبهم ثم اختبار بدائل الاستبدال.

## ذاكرة الأطروحة الاستثمارية

لكل سهم يمكن حفظ أطروحة قابلة للاختبار بدل ملاحظة نصية عامة. كل ركيزة تحتوي
على مقياس، وحد تأكيد، وإنذار، وكسر، ومصدر مؤرخ، والاختبار التالي المطلوب.

```bash
egx-portfolio thesis-check thesis.json \\
  --analysis-date 2026-09-21 \\
  --database egx-evidence.sqlite3 \\
  --output egx-output/thesis_evaluation.json
```

إذا كانت المعلومة قديمة أو لم تكن متاحة في تاريخ التحليل، لا يسمح لها بكسر
الأطروحة. تتحول الركيزة إلى غير مختبرة حتى يصل دليل صالح.

## قياس جودة القرارات

توجد طبقة مستقلة لقياس نتائج القرارات تاريخيًا. القياس يحسب:

- العائد الإجمالي.
- العائد بعد تكلفة التبديل المقدرة.
- عائد مؤشر المقارنة.
- العائد الزائد عن المؤشر.
- نسبة القرارات المربحة.
- نسبة القرارات التي تفوقت على المؤشر.
- أفضل وأسوأ نتيجة.

النتائج التي تحتوي على دليل لم يكن متاحًا وقت الإشارة تُستبعد افتراضيًا من
الملخص. الغرض هو منع تسرب معلومات المستقبل من تحسين الاختبار التاريخي بصورة
وهمية.

## منطق التصميم

الهدف ليس تعظيم عدد توصيات الشراء. الهدف هو تقليل القرارات الرديئة أولًا،
ثم ترتيب الفرص التي بقيت بعد الحواجز. لهذا السبب تفصل المنظومة بين:

`جودة الشركة -> السعر مقابل القيمة -> التوقيت -> المحفز -> السيولة -> الخطر
-> تكلفة التغيير -> أثر القرار على المحفظة -> متابعة الأطروحة -> قياس النتيجة`

تظل تغذية البيانات الحية الرسمية محكومة ببوابة الجاهزية أدناه. لا يتم اختراع
نقاط اتصال أو اعتبار مصدر غير مختبر جاهزًا للإنتاج.
